# 独自機能一覧の執筆・更新規則

`diff.md` は、Misskey-Tempura と本家 Misskey の違いを利用者に説明する文書です。アプリ内の `/tempura-changelog` も、このファイルを使います。画面用のコピーは作らないでください。

## 何を書くか

* 統合先ブランチの実装を確認し、利用できる機能と変更だけを書きます。未マージの実験や、取り消した変更を適用済みとして扱わないでください。
* 利用者に何ができるか、どこから使うかを先に説明します。ロール権限、管理者設定、制約があれば同じ項目に添えます。
* 本家にもある機能は、Tempura 固有の違いがある場合だけ書きます。
* 日付付きの変更欄には、変更点と利用者への影響をまとめます。日付は日本時間の統合履歴と照合し、コードから裏付けられない効果や数値は書かないでください。
* 継続的に使える機能は、日付付きの変更欄だけでなく該当カテゴリにも反映します。
* バージョン番号は `diff.md` に手書きしません。画面では、`package.json` から生成されるクライアントのビルドバージョンを `@@/js/config.js` の `version` から自動表示します。バージョンを上げる際に文書の番号を合わせる作業は不要です。
* 新機能や仕様変更は `diff.md` に追記します。`CHANGELOG.md` は明示的な依頼がない限り編集しません。

## 画面で扱える書式

GitHub とアプリ内で同じ内容を読めるよう、次の書式を使います。アプリのパーサーは Markdown 全体を解釈するものではありません。

| 書式 | 用途 |
| --- | --- |
| `# 文書名` | 文書全体のタイトル。画面の見出しには専用の翻訳を使います |
| 最初の `##` より前の通常文 | 画面冒頭の説明 |
| 単独行の `注意事項` と、その後の `* ` | 折りたたみ式の注意事項 |
| `## カテゴリ名` | カテゴリ切り替えと検索結果の見出し |
| `### 小見出し` | カテゴリ内のまとまり |
| `* 説明` | 機能の項目。件数はこの階層を数えます |
| 半角空白2個 + `* 補足` | 直前の項目の補足。入れ子は1段までにします |
| 字下げした継続行 | 直前の箇条書きの続き |
| `<!-- コメント -->` | 保守用メモ。表示・検索の対象外です |

通常文の連続行は1段落として扱い、空行で区切ります。カテゴリ内の通常文は小見出しの下、箇条書きの前に表示されるため、その位置に書いてください。箇条書き内のインライン装飾はアプリの MFM 表示に従います。HTML、表、コードブロック、番号付きリスト、4段階目以降の見出しは使わず、通常文と箇条書きに直してください。コメント内にも認証情報や非公開情報は置かないでください。

## 配信方法と設計理由

本文を JavaScript に埋め込まず、Vite の `?url&no-inline` で内容ハッシュ付きの独立した静的アセットとして出力します。クライアントにはその URL だけを含め、ページを開いたときに取得します。取得中は読み込み表示、失敗時は再試行ボタンを出します。通信には10秒の上限を設け、ページを離れたら中止します。

GitHub raw の `develop` を直接取得すると、古い版のサーバーにも未対応の機能を表示してしまいます。同じビルドのアセットを参照すれば、画面と説明の版が一致し、閲覧のために GitHub へ接続する必要もありません。

更新時はフロントエンドを再ビルドし、生成した JavaScript と静的アセットを一緒に配信してください。サーバー上のソース `diff.md` だけを差し替えても、配信済みの内容は変わりません。独自のアセット配信設定を使う場合も、この Markdown を配信対象から外さないでください。

## 更新時の確認

1. 対象ブランチのコミットと実装を読み、機能名・設定場所・制約を照合します。
2. `diff.md` を更新します。対応書式を増やす場合は、`packages/frontend/src/utility/tempura-script/feature-catalog.ts` とテスト、この文書も変更します。
3. `pnpm --filter frontend test test/unit/tempura-script/feature-catalog.test.ts` で、本文の取り込み・入れ子・検索・コメント除外を確認します。
4. `/tempura-changelog` でカテゴリ切り替え、別カテゴリの語句検索、狭い画面の表示を確認します。取得に失敗したときの再試行も確認してください。
5. コードを変更した場合は、`AGENTS.md` と `shipping-misskey-change` の検査を通します。
